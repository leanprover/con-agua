# Lane d37: the twin's `clear_fit` for the `instantiateList` memo

Task: lnext3's rank 4 (docs/design/lnext3.md §1.3, "Next steps" 4), deviation D37 for the memos.

## The twin

con-ron's `HashMap2::clear_fit` (`ron/hashmap2.rs`), which `reset_map` (`arena/core_state.rs`)
uses at every per-call and per-declaration reset: the mark `fit_hw := max(entries, fit_hw -
fit_hw / 8)`; the wanted size `pow2_at_least(2 fit_hw + 1, 32)`; the table is re-made (lazily)
when that is above its slot count `n` or `n / 64` is above it, and otherwise only the epoch is
bumped. L's memos (`MemoLib`) instead returned to their default region (`MN0` = 16,384 slots
from slot 1) at every clear: the header that names a grown region carries the stamp, and a clear
makes it stale. On app-lam the `instantiateList` memo (`ilSch`, `inst_list` clears it before and
after its walk) grows inside many calls from that default every time: lnext3 measured 2.07 G of
`ilm_put`'s 4.39 G instructions in its growth.

## Prototype

call to a hand-written routine (`_tmp/d37/pC.s`; `p32.s`, `p16k.s` for the variants). Exact
instructions (`perf stat -e instructions:u`, one run each, `--jobs=1`):

| | base | `p32` (twin, floor 32) | `p16k` (twin, floor `MN0`) | `pC` (floor `MN0`, fast path) |
|---|---:|---:|---:|---:|
| app-lam | 41.648 G | 38.750 G (−7.0 %) | 38.748 G (−7.0 %) | 38.974 G (−6.4 %) |
| beta-ladder | 11.200 G | 11.287 G (+0.8 %) | 11.129 G (−0.6 %) | 11.200 G (0.0 %) |
| c05b | 12.045 G | 12.101 G (+0.5 %) | 12.060 G (+0.1 %) | 12.048 G (0.0 %) |
| `Init` | 214.002 G | 215.931 G (+0.9 %) | 215.118 G (+0.5 %) | 214.367 G (+0.17 %) |

* The twin's floor of 32 slots makes small rounds grow from 32 (beta-ladder, c05b, `Init`
  worse); L's default region is the better floor.
* With 52 M clears on `Init`, every instruction the clear adds costs 0.024 %: the full policy at
  every clear (`p16k`, ~21 instructions more than the bump) is +0.5 %. `pC` adds a fast path:
  when the stored mark is `0` and the round's count is at most `FITLO` = 8,191 (so `2 hw + 1`
  fits the floor), the clear is the epoch bump plus two compares; a decayed mark of at most
  `FITLO` stores `0` and leaves the header stale (the default region). This differs from the
  twin only at the floor: the twin's slack rule would keep a region of up to `64 · MN0` slots for
  a mark that decayed to the floor, `pC` returns to the floor (the twin's floor is 512 times
  smaller, so its slack never keeps more than 2,048 slots for a small mark).
* Peak RSS unchanged (app-lam 1,762 / 1,763 MB, `Init` 696 / 710 MB, c05b 132 MB).

Wall (`_tmp/bce/wb2.py`, 20 interleaved rounds, CPUs 8,56, load 15.6–21.8; `wstats.py`):
app-lam −0.7 % (p 0.31; [−4.3, +1.3]), beta-ladder −0.1 % (p 1.0), c05b +2.0 % (p 0.15;
[−1.8, +7.1]), `Init` 0.0 % (p 0.48; [−1.0, +2.7]): no significant change. User cycles on
app-lam (`perf stat -e cycles:u`, 5 alternating runs, CPU 8): base median 36.02 G, `pC`

**Go**: app-lam −6.4 % instructions (≥ 2 %), `Init` not regressing in wall time (+0.17 % in

## Change

**MemoLib** (`Arena/MemoLib.lean`), generic in the schema like the rest of the library:
`memoClearFitG S` (`X_clear_fit()`), next to `memoClearG`:

* the epoch bump of `X_clear` (stamp `CTL[cs]` + 1, count `CTL[cs + 1]` := 0, abort where the
  stamp would wrap); the count `c` is read first;
* the **mark** is the header's word 3 (the header slot's value word: no region covers slot 0, and
  no other code reads it). If it is `0` and `c ≤ FITLO` (8,191): nothing more (the header is stale,
  the next round has the default region). Otherwise `h := max(c, h - h / 8)`; if `h ≤ FITLO`, store
  mark `0` (default region); else `mfitBlkG`: `w := pow2_at_least(2 h + 1, MN0)` (a doubling loop,
  `mfitLoopG`, stopped at `2^62`), the current size `n` (the header's, or the default), the twin's
  policy `n := w` if `n < w` or `n / 64 > w`, capped at the slots after the header, and the new
  header: stamp `s + 2` (the new live stamp), region from slot `1`, size `n`, mark `h`.

Its model `mclearFitG` is `mfitTail (mclearG S m) …` (the bump, then the tail); `mfitHdr`,
`mfitNE`, `mfitPol`, `mfitCur`, `mfitL`, `mfitHW`, `mpow2` are the pieces. Specs:
`mfitLoopG_spec` (induction on the fuel, `mpow2_step`/`mpow2_end`), `mfitBlkG_step_spec`,
`mfitTailG_step_spec`, `memoClearFitG_spec` (`s'.mem = mclearFitG S s₀.mem`, the same shape as
`memoClearG_spec`), all `vcgen` + `finish`. `mclearFitG_fast`: with mark `0` and `c ≤ FITLO`,
`mclearFitG = mclearG`.

**The fast path is in the caller.** `memoClearFitG` is no leaf the inliner takes (more than 80
nodes), so a call per clear: the first build (every `inst_list` clear a call of
`memoClearFitG`) measured `Init` +0.39 % instructions (214.836 G), 16 per clear. Now `inst_list`
(`Arena/InstListSpec.lean`) tests the fast path itself and calls `ilm_clear` (`memoClearG`,
inlined) or `ilm_fit` (`memoClearFitG ilSch`, new): `Init` +0.22 %. `instListW` is unchanged
in shape (`mclearFitG` where it had `mclearG`); the proof takes both branches (`ilm_fast`).

`ilm_fit` joins `checkerProg` (1819 functions) and the lists that hold `ilm_clear`: by hand
`CoreErec`, `IndMemoFns`, `WriteSets.instListFns`, `PhaseBReads`, the six lists of
`Checker/IndArmFns.lean`; by their scripts `loopFns` (`loop_fns.py`), `nvFns` (`nv_fns.py`);
`leaf_fns.py` leaves `leafFns` as it was (neither function is a leaf of the core's memos).
`checker_prog.py` regenerated `Prog.lean` and the parts; **`asm_file.py` must run after the
`ProgI` parts are rebuilt** (it builds `Checker.Prog` only): run right after
`checker_prog.py`, it emitted a `checker.s` from the stale `ProgI` oleans (one function more
shifts every part's range) that `checkerFile_eq` rejected (segment 18, `alpd_go`) and whose binary
fails on the prelude; after `scripts/lake build` it is right.

## Proof

  one, with a region from slot `1` within the array or none, and a header stamp not above the
  live one, is `∅`); `memoRV_fresh` is now its instance (default region). `mclearG_stamps` (the
